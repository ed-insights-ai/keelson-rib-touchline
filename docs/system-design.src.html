TOUCHLINE PROTOTYPE · DESIGN CONCEPT

How a machine scouts a season

Published data in · every number computed · every claim graded and cited ·
a coach-grade briefing out, repeatable across programmes
PURPOSE
A briefing you can check
not one you must take on faith

College soccer publishes nearly everything a scout needs — schedules, rosters, player statistics, a box score for every match — on the athletics sites every programme already maintains. What almost no programme below the top divisions has is the analyst to assemble it. The Touchline prototype tests whether a system pairing deterministic computation with a language model held to an evidence standard can do that assembly and return a preseason briefing a coaching staff can verify line by line. These pages show the design, the measurements, and the learnings.

The system in one view

Five layers, two kinds of worker, and one place where a model is allowed to be wrong.

Four layers are ordinary software: deterministic, tested, and boring the way data infrastructure should be. One is generative. In the vocabulary of current AI research, the pattern is retrieval-grounded generation — the model writes only from retrieved, dated sources and computed figures, never from its own parametric memory — followed by an adversarial model-as-judge verification stage, with machine-checked guardrails between every generative step and full data lineage from archived page to printed claim:

04

The determinism boundary

Code computes every number. The model writes only words. Here is what that looks like on a real page.

Below is an actual excerpt from the Harding briefing — the executive brief's numbers panel. Everything in it was authored by exactly one of two workers, and a reader can always tell which:

COMPUTED · CODEThe stat tiles and the goals-by-minute chart are drawn by the renderer from digest fields. No model can alter a box, a bar, or a value.
WRITTEN · MODELThe paragraph is the model's — but every figure inside it is quoted from the digest, and every non-numeric claim traces to a cited finding.
ONE BRIEFING, BY AUTHOR · HARDING RUN, MEASURED
the 1,932 numbers
100% computed by code
the 4,502 words on the pages
62% drafted by the model
38% code-set labels
every chart & graphic
100% drawn by the renderer

The generative surface is enumerable: the model authors roughly three of every five words and none of the numbers or graphics. Hallucination risk is confined to sentences — exactly the surface the evidence standard of section 05 governs.

Never published: a number the model wrote. If a figure appears anywhere in the briefing, code produced it from the archive. The model's contribution is prose, and prose claims carry citations.

The seam between the two workers is a versioned narrative contract: a JSON schema of prose slots the model must fill and the renderer composes. It evolves additively, like an API — when the system learned to reason about coaching tenure, the schema gained one optional field and every earlier narrative remained renderable. The narrative is also the one artifact a rerun cannot reproduce: the model's reading of a programme at a moment in time, against that day's web. So it is kept, beside the PDF it produced, as a pair.

Takeaway. Deciding what the model is not allowed to author did more for quality than any prompt refinement. A generative system becomes auditable at the moment a reviewer can point at any element of the output and say which worker produced it and which check covers it.

05

Research as evidence, not recall

The model is a reader of sources, never a source. Retrieval, grading, refutation — measured below.

A model asked "what do you know about this programme?" answers fluently from training data of unknown age. The prototype never asks that question. Its researcher searches the live web and files findings — each a claim with a source, URL, date, and a source-strength grade — and a second pass, prompted to refute rather than confirm, attacks every one. Each dropped finding carries a named reason — one reads, in full: "The source page returned HTTP 403 Forbidden on re-fetch." Restricted findings print only with their source kind named and never as sole support. Alongside the pool, the verifier records what it could not sweep — 18 flagged corners — so even the unread is on the record.

A FINDING, AS THE SYSTEM STORES IT
claim:     "New head coach hired ahead of the 2026 season"
coach:     { name, status: new, since_season: 2026 }
source:    athletics-site staff announcement  · url · dated
confidence: high → verify: confirmed  · eligible for print, any claim

Downgrade, never delete. What fails refutation stays in the pool at reduced standing: the record of what was checked and found wanting prevents the next run from rediscovering the same false lead, and leaves an audit trail a human can read. The grades themselves are the researcher's own source-strength reports — uncalibrated, which is why the print threshold, not the grade alone, decides what reaches the page.

The bench lens. The highest-leverage qualitative fact turned out to be the coaching bench: a new coach makes last season's film provisional; tenure makes patterns inferable. It entered the system as a structured object flowing through the same grading, refutation, and gates as everything else — today's map reads 5 returning, 1 new, 1 unknown, and unknown is a legal value that prints as such.

Takeaway. "AI insight" here means a machine read more pages than a staff had time to, and wrote down what it found, where it found it. The intelligence is coverage and synthesis — never the model's memory.

Guardrails: the model declares, the validator decides

Mechanical gates between every generative step — because one day the model said "done," and wasn't.

THE STYLE CONTRACT · JUDGMENT, GOVERNED IN PROSE
Tiering is data coverage, never judgment. An opponent gets a smaller card only because less is published about them; uncertainty is expressed inside a full card, in words — the report's shape describes the evidence, not the author's mood.
Absence is promoted, not absorbed. The unpublished roster on page 3's matrix surfaces as a printed cover caveat and a table footnote — computed, so the notes vanish on the first run after the school publishes.
A rule moves from prose to gate the moment it is stated precisely enough for a script to check. One rule found by human diff — a fully-covered programme mis-tiered — is now written contract; the structure that makes such drift visible is machine-checked.
Takeaway. Prompts steer; only gates guarantee. The reliability of a multi-step generative system is the product of the checks between the steps, not the eloquence within them.

The reproducibility test

Same prompts, contract, validators, renderer — three programmes. The claim is the diff, and it is measured.

A system like this is easy to tune into a one-team demo. The acceptance test was to run it where it was not tuned and compare. These are the three briefings, as produced:

Harding · 17 pages · the tuning subject
Fort Hays State · 17 pages · first cold run
Newman · 18 pages · weakest published data
THE SAME SKELETON, PAGE BY PAGE · LENGTH DRIVEN BY DATA, NOT PADDING
coverexecutive brieffocuslandscapeopponent cardswatchlist
Language reuse, measured — not asserted. Cross-narrative 5-gram Jaccard overlap between any two briefings: 3.4%. Every shared 8-gram is a data artifact — a source URL or a citation line — not template language. The contract constrains form; it does not leak phrasing.
Perspective travels with the evidence. The one verified coaching change appears in two briefings from two lenses — a programme's own story in one, an opponent's threat in the other — from the same finding object.
Weak data degrades honestly. Newman's positionless published roster surfaced as "position unlisted," and a returner's usage collapse was flagged from the minutes ledger rather than smoothed over.

A finding worth the price of the prototype. An exemplar report initially rode along as a quality reference — and its phrasing leaked into every output. It was removed entirely; the quality bar now lives in written contracts and validators, which constrain without being copyable. Contracts generalize; examples imprint. Two gaps found in these comparison runs became contract rules; the third run was clean.

Takeaway. Reproducibility was treated as a gate, not a hope: run the system where it was not tuned, diff the results, and let every gap found become a rule in the contract or a check in a gate. For any system of this type, the cold run on a second subject is the single most informative test that exists — schedule it early.

The living season, and the learning lane

A briefing is a run, not a document. New data keeps arriving; old data is a training substrate.

The preseason briefing is the season's first run, not its last. A box score is published within hours of the final whistle, and everything on these pages — collect, curate, analyze, interpret, render — is a circuit, not a one-time build. The empty 2026 column on page 3 fills match by match, and every fill is one rerun away from a current briefing:

In-season value is a freshness property, and freshness is exactly what the architecture already buys: because every store derives from the archive, "up to date" means "rerun," never "rebuild."

The two lanes justify each other. The learning lane is honest future work — no predictive model ships in the prototype — but it is enabled now, because its precondition is not modeling talent; it is a decade of clean, reconciled, never-pruned history, which is precisely what the collection rules of section 03 have been quietly accumulating. And any model trained there inherits the same discipline: its predictions would enter the briefing as one more graded, sourced finding — computed by code, attributed, and checkable — never as oracle text.

09

What building it taught

Eight learnings for anyone attempting a system of this type, in any domain where evidence matters.

1 · Put a gate after every generative step. The model's claim that work is complete is a request to be checked, never an exit condition.
2 · Draw the determinism boundary early; never let a number cross it. Code computes, the model writes — and the system becomes auditable the moment its generative surface is enumerable.
3 · Use the model as a reader, never as a source. Findings come from the live web with source, date, and grade. A claim without provenance does not exist.
4 · Grade evidence; never delete it. A refuted claim, downgraded and kept, protects every future run. A cleaned pool is a less trustworthy one.
5 · Contracts beat examples. Written rules plus validators reproduce quality across subjects; a reference sample imprints its phrasing on everything it touches.
6 · Absence is data. Compute the gaps and print them; a derived caveat heals itself when the data arrives, where a hand-written one goes stale and lies.
7 · Archive primary sources; treat every store as derived. The raw pages plus their URLs are the record. Everything else must be regenerable from them, forever.
8 · A report is a run, not a document. Design for the rerun from day one — freshness in-season and trainability across seasons both fall out of the same decision.
THE IMPLEMENTATION, BRIEFLY

The prototype runs on a local agent workbench, packaged as an installable extension: four declarative workflows (collect, report, player-profile, data-integrity) sequencing shell steps, agent loops, and validator gates; a Python pipeline for scraping, parsing, digest, and rendering; prompts as versioned, reviewed files. Reports are composed as HTML by code, printed by a headless browser, and machine-verified page by page. The data home separates evidence (the research pool, tracked), deliverables (narrative-and-PDF pairs), and scratch (regenerable intermediates).

STATED LIMITS · WHAT THIS PROTOTYPE HAS NOT SHOWN
One conference, one season, and a three-run reproducibility evaluation — not a controlled study. No predictive-validity test yet (does the briefing's reading correlate with season outcomes?), and no user study with coaching staffs. Confidence grades are the researcher's own uncalibrated source-strength reports, constrained downstream by the print threshold rather than calibrated upstream. A research audience should read these pages as a working method with measured internal properties, and an evaluation agenda stated in the open.

For the researcher, the contribution is the composition — deterministic computation with retrieval-grounded, adversarially verified, gate-checked generation — and none of it is soccer-specific. For the coach and the athletic director, the argument is simpler: the information advantage that used to require an analytics staff is now a question of assembling public data carefully, and trustworthiness is a property you can demand and check — every number computed, every claim cited, every gap named.

This report states the design of the Touchline prototype as built, with all counts measured from the system's own stores on the date of writing. The moving detail lives with the code: the workflow definitions carry the run graphs and gates, the prompt files carry the research protocol and style contract verbatim, the pipeline carries the collectors, parsers, digest, and renderer, and each data home carries the archive, the evidence pool, and every briefing pair produced. Where these pages and the code disagree, the code is current and these pages are history.
